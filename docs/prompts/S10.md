## From S8

The command, and the pieces you can reuse without it.

```sh
uv run python -m vorpal.cli --draft-id ID --operator NAME --once
```

`FANTASYPROS_API_KEY` from the environment. `--scoring-league-id` only for
a standalone mock, `--override CSV` only when FantasyPros is down, `--slot`
only when the draft order is partial. Drop `--once` for the poll loop; it
runs until `draft.status == "complete"`. There is no console script:
`pyproject.toml` is shared and adding one is a root PR.

For the dress rehearsal, `main` takes injectables so you do not have to
shell out:

```python
from vorpal.cli import main

code = main(argv, client=None, transport=None, sleep=time.sleep, now=time.monotonic)
# 0, or 2 with a refusal already printed to stderr
```

Pass `client=` to swap the host; it is typed `platform.LeagueClient`, a
protocol, so any object with the six read methods works. Leave it None for
`SleeperClient`.

Pass `transport=` to swap the model; leave it None for the live
`AnthropicTransport`. `main` calls `propose`, which retries once and then
degrades to the calculator. **That is the draft-night path, not the eval
path** — for the table, build payloads and call `recommend` /
`run_stability` yourself.

`main` does not recompute or re-ask on every poll. `_Frames` caches one
built board per `(pick_no, status, pick_timer)`, and `_Proposals` calls the
model only on the first board and on picks within two of the operator's
seat, reusing the last answer otherwise. If you count model calls in a
rehearsal, count what `propose` sees, not what the transport sees —
`propose` retries once.

To build payloads without the CLI:

```python
from vorpal.payload import build_payload, build_rows, build_state
```

`build_state` gives you SPEC.md section 4 `state` from the resolved config
plus the picks; `build_rows` gives you capped `BoardRow`s with
`delta_starter_points` filled. Signatures and the caps-before-delta reason
are in `docs/handoffs/S8.md`.

Gotchas that will cost you an hour otherwise:

- **The forecast is fetched once per process.** `vorpal.ingest.clear_caches()`
  between fixtures, or the second one silently reuses the first.
- **`vorpal.cli.FP_MIN_INTERVAL_S` is 1.1 seconds** and there are eight
  FantasyPros calls. Patch it to 0 for anything that is not a live run.
- **Time the rehearsal against `draft.pick_timer`, not the poll rate.**
  The page greys out at the timer; the loop polls at 3s while `drafting`
  and 15s otherwise, including `paused`.
- **`--players-cache` keeps `/players` out of your home directory.** The
  cache is 24 hours; a rehearsal that re-fetches it is your own doing.

## From S9

Full detail in `docs/handoffs/S9.md`. The two READMEs
(`tests/golden/README.md`, `tests/regret/README.md`) say what the data
does not cover; read them before you write a verdict.

`tests/` is not a package. Each directory adds itself to `sys.path` in
its own `conftest.py`; from `evals/` do the same two lines first.

```python
from cases import CASES, GoldenCase  # tests/golden
from replay import all_fixtures, load_fixture  # tests/regret
```

**Golden — 12 cases.** `case.fixtures()` returns a `GateFixtures` with
`forbid` and `require` set and every other field `None`. Add the rest
with `dataclasses.replace(case.fixtures(), stability_ids=five_ids)`.
`case.why` is the human sentence; print it beside any failure.

**Regret — 4 fixtures, 3 drafts.** `fixture.gate_fixtures(board_ids)`
fills `available_at_next`. Pass the **whole board**, not a drafted set:
a player that room never took was available the entire time. Also
`fixture.board_at_pick(board_ids)`, `fixture.actually_picked`,
`fixture.era`, `fixture.provenance`.

Three things to carry into the report:

1. **`argmax_vols` already fails 3 of the 12 golden cases** cold, and
   passes the other nine. Three cases is the whole separation this set
   can show. Do not report a golden pass rate as if twelve boards were
   twelve independent measurements.
2. **`bye_hole` fails both candidates in the `bye_stack` case.** The
   gate compares alternatives only in the recommendation's own bye week,
   so with a short position it is symmetric and cannot see a stack. If
   your table shows `bye_hole` failing nearly everything, that is why.
   It is a spec question, not a patch — section 5 defines the gate
   exactly as built.
3. **`replay` is `NOT_PERFORMED` everywhere.** S9 has no dated
   projections file, so `dated_points`, `user_lineup` and
   `policy_lineup` are all unset. Report it as a skip, never as a pass.

`stability_ids` and `replacement_rank_delta` are yours: five real model
calls, and S4's rank deltas over the full pool.
