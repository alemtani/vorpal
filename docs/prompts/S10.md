## Copy-paste prompt

```
Read docs/SPEC.md, docs/PLAN.md, and every file in docs/handoffs/, then
docs/prompts/S10.md.

Run the evals for real and report what they say.

git worktree add ../vorpal-s10 -b feat/eval-run main

Stability calls: `vorpal.model.run_stability(payload, transport)` returns
the five proposals, or `None` when `coin_flip` is true. Do not open a
sixth call. This runner and `recommend` are the eval path — both raise on a
violation, which is the score. Draft night calls `propose` instead, which
retries once and then degrades to the calculator; do not use it here.
Signatures: `docs/handoffs/S5.md`.

1. Run all eleven gates over every fixture, for the model and for all three
   baselines. Include the stability gate: five identical payloads, at least
   three matching player_ids, skipped on coin_flip.

2. Produce the four-column table: model, argmax_vols, adp_follow, ecr_follow,
   one row per gate. Report NOT_PERFORMED counts separately from failures —
   never fold a skipped gate into a pass rate.

3. Read the table honestly. Any gate where the model and argmax_vols post the
   same rate has no discriminating power, and SPEC.md section 5 is explicit:
   the model separates or it is not paying for its tokens. If it does not
   separate, say so in the report. Do not tune the gates until it does.

4. Dress rehearsal: run the whole tool against a live standalone mock draft,
   end to end, under the real poll loop. Time the loop against a real pick
   timer. This is the only test of the thing that actually matters on draft
   night — that you can read the board and act before the clock runs out.

Write the report to evals/REPORT.md. Include what failed and what you did not
measure.

Finish with the four handoff steps in docs/PLAN.md section 5.
```

## Definition of done

- `evals/REPORT.md` with the four-column table and NOT_PERFORMED counts.
- A written verdict on whether the model separates from `argmax_vols`.
- One timed dress rehearsal against a live mock draft.
