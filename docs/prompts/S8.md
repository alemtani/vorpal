## Copy-paste prompt

```
Read docs/SPEC.md, docs/PLAN.md, and every file in docs/handoffs/, then
docs/prompts/S8.md.

Wire the modules into one command. You own src/vorpal/cli.py and nothing else.

git worktree add ../vorpal-s8 -b feat/cli main

Inputs per SPEC.md section 2: draft id, operator (username or user_id),
scoring-source league id (required iff draft.league_id is null), optional
override CSV path, FantasyPros API key from the environment.

Flow: read draft -> resolve slots, scoring, seat, adp variant (S3) -> fetch
players and picks (S1) -> fetch projections and ECR once (S2) -> score and
value (S4) -> build payload (S5) -> call the model (S5) -> render (S7) -> loop.

Rules:
- Projections and FantasyPros are fetched ONCE per process, before the loop.
- Refusals print to stderr and exit 2. UnsupportedLeague, DataRefusal and
  PlatformError stay distinct in the message; do not collapse them.
- Banners surface before the board renders, never after.
- No feature logic lives here. If you find yourself computing something, it
  belongs in a module and you should open a PR against that module instead.

End-to-end test: fixtures in, a stubbed model response, a rendered page out.
No live network in CI.

Finish with the four handoff steps in docs/PLAN.md section 5.
```

## Definition of done

- One command runs fixtures end to end and writes a board.
- Each refusal class exits 2 with its own distinguishable message.
- No business logic in `cli.py`.
