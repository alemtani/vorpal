```
Read docs/SPEC.md, docs/PLAN.md, docs/handoffs/S0.md, then docs/prompts/S2.md.

Build src/vorpal/ingest/ — the three non-Sleeper-documented data sources.

git worktree add ../vorpal-s2 -b feat/ingest main

Three readers, each returning contracts types:

1. Projections. GET https://api.sleeper.com/projections/nfl/{season}
   ?season_type=regular&position[]=... Season totals only (week is null). Keyed
   by Sleeper player_id. Fetch once per process; never poll. Enforce a single
   company (currently rotowire) or raise DataRefusal.
   HARD RULE: never ingest pts_ppr, pts_std, pts_half_ppr, or any other
   fantasy-point column. Counting keys only. Write a test that fails if a
   pts_* key survives into a StatRow.
   Rows with ADP and no stats are market-only: keep them, mark them, and let
   valuation exclude them from VOLS.

2. FantasyPros consensus rankings. Returns rank_ecr, rank_min, rank_max,
   rank_std. Join to Sleeper on yahoo_id. Scoring param STD/PPR/HALF follows the
   rec-weight rule; superflex uses position=OP.
   A join miss omits ECR on that row and increments a banner count. It is not an
   error. FantasyPros being down banners ecr_missing and returns no ECR at all —
   it must never block a draft.

3. Override CSV keyed by player_id. Required column player_id, plus the counting
   stats the scoring keys need, plus adp. Optional adp_stdev, name, team, pos.
   Replaces stats and ADP wholesale when the projections host is down. No name
   matching, ever. Projections down and no override supplied is a DataRefusal.

Also here: the fail-closed mapping report. Match on player_id where you have it;
where you must match players across sources, use name+pos+team then name+pos
with a team-mismatch flag. If the match rate on the top 300 by ADP is under 98%,
raise DataRefusal and print the report.

Do not compute the ADP variant here — S3 resolves it from slots and returns
which key to read. Take the variant as an argument.

TDD: failing test first. respx for transport. Fixtures only, no live calls.

Finish with the four handoff steps in docs/PLAN.md section 5.
```

## Definition of done

- A test asserting no `pts_*` key can reach a `StatRow`.
- ECR-absent path produces a banner and a usable result.
- Mapping report tested at both sides of the 98% threshold.
