```
Read docs/SPEC.md, docs/PLAN.md, docs/handoffs/S0.md and docs/handoffs/S4.md,
then docs/prompts/S5.md.

Build src/vorpal/payload/ (board assembly and serialisation) and
src/vorpal/model/ (the call). SPEC.md section 4.

git worktree add ../vorpal-s5 -b feat/payload-model main

Payload:
- Build the board from BoardRows. Order by vols descending. Cap at top 50
  overall, plus top 10 per position, plus every player whose adp falls inside
  the next two rounds. The union, not the intersection.
- State in the payload that the board is capped. The model must not read
  scarcity off a truncated list.
- The board is the world: the recommendation and every alternative must be ON
  the board, not merely undrafted.
- Omit next_user_pick, picks_until_next and between when the seat is unknown.
  Do not guess a seat. Do not ship a survival band — wait-vs-take is the
  model's, not yours.
- hint_argmax_vols is a calculator output, not the answer. Ship it as such.
- Serialise to exactly the shape in SPEC.md section 4. Assert the key set in a
  test against the contracts type from S0.

Model:
- One call per board change. No tools. Closed world. The spec explains why
  (section 4): every round trip runs against the pick timer, and the stability
  gate needs identical payloads to converge. Do not add tools, do not set
  temperature — it is rejected on current models.
- Schema-constrained output: player_id, alternatives, slot_filled, coin_flip,
  why, flags. flags is a closed enum:
  ECR_DISAGREE | BYE_STACK | POSITION_RUN | EMPTY_STARTER | UPSIDE | VOLS_DISSENT.
- Validate the response before anyone sees it. Ids not on the board fail the
  call. Rec != hint_argmax_vols without VOLS_DISSENT fails the call — silent
  dissent is a failure, not a warning. Rec beyond ecr_best + margin fails; the
  ECR_DISAGREE flag does not save it.
- Stability runner: send five identical payloads, return the five responses.
  coin_flip true skips it. This is called by the eval run, not by draft night.

Testing: stub transport plus a recorded response for all unit tests. A live
call runs only under @pytest.mark.live and never in CI. Check the model id
against the claude-api skill rather than hardcoding one from memory.

TDD: failing test first.

Finish with the four handoff steps in docs/PLAN.md section 5.
```

  appears when their ADP lands in the next two rounds.
- Every validation failure in §4 has a test that proves the call fails.
- No live network call in the default `pytest` run.
