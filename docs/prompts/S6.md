## From S5

The five-call loop is `vorpal.model.run_stability(payload, transport)`.
It returns `tuple[Proposal, ...]` or `None` when the first response has
`coin_flip is True`. Do not send five calls yourself. The stability *gate*
is still a pure function of those five proposals (or `NOT_PERFORMED` on
`None` / `coin_flip`).

`validate_proposal(payload, raw)` returns
`tuple[Proposal | None, tuple[Violation, ...]]` and **never raises.** Count the
violation codes — they are the call-validation score. `recommend` wraps it and
raises on any violation, which is what you want in an eval; `propose` retries
and degrades, which is draft night. Do not use `propose` here.

Call validation already reports silent VOLS dissent (`silent_vols_dissent`) and
ECR beyond margin (`ecr_beyond_margin`). Your XOR gates still apply: agreeing
with the hint *and* setting `VOLS_DISSENT` is a gate fail, not a violation. Same
for `ECR_DISAGREE`.

The board cap is slot-aware now, and has no ADP arm: it is top 50 by VOLS
union per-position depth. `vorpal.payload.position_depth` and `remaining_need`
are exported so a gate can assert what the board should have held for a given
`needs`. A market-only row never reaches the board.

## From S0

Each gate returns `GateResult(gate, outcome, reason)`. `GateOutcome` is
`PASS` | `FAIL` | `NOT_PERFORMED`. The eleven `Gate` values are `schema`,
`golden_forbid`, `golden_require`, `vols_dissent`, `ecr_dissent`,
`ecr_sanity`, `bye_hole`, `stability`, `vols_invariant`, `regret`,
`replay`. Field list: `docs/handoffs/S0.md`.

Baselines produce a `Proposal` with `Flag`s set mechanically.

Signatures: `docs/handoffs/S4.md`.

```python
from vorpal.valuation import (
    MAX_REPLACEMENT_RANK_SHIFT,  # 2
    compute_vols,
    hypothetical_replacement_ranks,
    replacement_rank_shifts,
)

result = compute_vols(players, slots, teams)
extra = hypothetical_replacement_ranks(players, slots, teams, result)
shifts = replacement_rank_shifts(result.replacement_ranks, extra)
# vols_invariant FAIL iff any shift > MAX_REPLACEMENT_RANK_SHIFT
```

Gotchas:

- The solver already ran two passes. This extra fill is the eval, not a
  third pass. Do not change valuation to make the gate pass.
- A failure is a model problem. Report `FAIL`. Do not paper over it.
- `replacement_ranks` is the 1-indexed positional index of the first
  unabsorbed player at that position.
- `@pytest.mark.invariant` already exists. Marker failure is a model
  problem, not a code bug.
