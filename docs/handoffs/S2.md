# S2 handoff

Ingest. FantasyPros is the forecast host: projections, ADP, ECR, bye.
Override CSV when that host is down. One join path onto host player ids.

Worktree is `feat/ingest`.

## What S8 calls

```python
from vorpal.ingest import load_forecast, load_stat_rows, clear_caches
from vorpal.contracts import AdpVariant

stat_rows, ecr_rows, banners = load_forecast(
    season,  # draft.season, e.g. "2026"
    adp_variant,  # from S3; do not compute it here
    ecr_scoring=config.ecr_scoring,  # "PPR" | "HALF" | "STD"
    superflex=superflex,  # SUPER_FLEX / OP / 2+ QB slots
    host_players=players,  # client.get_players(): Mapping[str, Player]
    override_path=path_or_none,  # optional CSV
    fp_api_key=os.environ.get("FANTASYPROS_API_KEY"),
    min_interval_s=1.1,  # live FP is 1 call/s; tests use 0
)
```

`host_players` is generic `Player` rows. The cross-source join key rides
on `Player.external_ids` as `(source, id)` pairs — Sleeper's adapter emits
`("yahoo", ...)`. No host wire name reaches `ingest/`.

`load_forecast` fans stats and ECR as parallel futures, then joins. They
do not depend on each other. A shared `FantasyProsClient` rate-limits
the HTTP.

Returns:

- `tuple[StatRow, ...]` — counting keys mapped onto host scoring names.
  `adp` is already the chosen variant. `market_only=True` means ADP (or
  empty stats) and no counting keys; S4 excludes those from VOLS.
- `tuple[EcrRow, ...]` — host `player_id` after join. Empty if FP ECR is
  down.
- `tuple[Banner, ...]` — surface before the board.

Banner codes:

| code | when |
|---|---|
| `ecr_missing` | no API key, or FP ECR HTTP/JSON failure |
| `ecr_join_miss` | FP rank could not join; count in the message |
| `ecr_team_mismatch` | joined on name+pos; teams differed |
| `projections_override` | FP stats were not used; CSV supplied stats+ADP |
| `adp_missing` | ADP list empty or down |
| `adp_1qb_market` | 2QB/OP ADP was empty; 1QB ADP was used |
| `projection_join_miss` | FP stats row could not join (98% gate still ran) |
| `unmapped_scoring_keys` | league scoring key with no projected counting stat |

Parse-only entry points (fixtures, no HTTP):

```python
from vorpal.ingest import (
    parse_projections,  # payload -> tuple[ProjectionRecord, ...]
    parse_ecr,  # payloads, host_players -> (EcrRow..., Banner...)
    parse_override,  # csv text -> tuple[OverrideRow, ...]
    fetch_projections,  # season, client=; process-cached
    fetch_ecr,  # season, scoring=, superflex=, host_players=, client=
    load_override,  # path -> tuple[OverrideRow, ...]
    load_stat_rows,  # projections or override, then mapping gate
    FantasyProsClient,
)
```

`AdpVariant` maps to FP ADP: `2qb` → `position=OP`; else `ALL` with
STD/PPR/HALF. There is no `adp_2qb_ppr`. Do not import
`ADP_WIRE_KEYS` from the Sleeper adapter.

Process caches: one projections fetch per season, one ADP fetch per
`(season, scoring, position)`, one ECR fetch per
`(season, scoring, superflex)`. Never poll. Tests call `clear_caches()`.

## Mapping

Match `host_id` (override CSV, or an optional Sleeper id on the FP
row). Then `yahoo_id`. Then name+pos+team. Then name+pos with a team
mismatch flag. DST/DEF are the same position. Ambiguous name+pos is a
miss. FantasyPros numeric `player_id` is not a host id.

Rate is on the top 300 by ADP (lowest first). Under 98% raises
`DataRefusal`; the message *is* the report. 294/300 passes. 293/300
refuses. If no row has ADP, the gate uses the full set.

Override path never name-matches. Projections path may.

Recorded `tests/fixtures/sleeper/players.json` is a subset. E2E fixtures
must supply a player map that includes the projected ids, or the gate
fires.

## Spec vs this session

1. **Forecast is FantasyPros.** Sleeper projections are not used. The
   recorded `tests/fixtures/projections/season_regular.json` file is
   leftover Rotowire bytes.
2. **Key map is per host**, like S3 `SCORING_KEY_GROUP`.
   `FP_TO_HOST[Host.SLEEPER]` maps FantasyPros names onto Sleeper
   `scoring_settings` keys (`pass_yds` → `pass_yd`). ESPN is empty until
   that adapter adds rows. `points` / `pts_*` totals never reach
   `StatRow`. Coarse `fg` and `pa` are dropped so we do not invent
   buckets.
3. **Bye** comes from FantasyPros (`player_bye_week`), not host
   `/players`.
4. **ECR is one overall list.** `ALL` in 1QB with `type=draft` (`ALL`
   without `type` is HTTP 400). Superflex is `OP`. `rank_ecr` is overall
   draft order. Do not stitch positional lists.
   A join miss omits that row and banners the count. FP ECR down
   banners `ecr_missing` and returns no ECR. Neither blocks a draft.
   Stats down with no override is `DataRefusal`.
5. **Yahoo first, then name.** Host DEF `yahoo_id` is often null. Name
   +pos+team recovers DST (`Houston Texans` → `HOU`). FP `JAC` vs host
   `JAX` is name+pos with `ecr_team_mismatch`.

## What S2 did not do

- No ADP-variant policy (S3).
- No VOLS, scoring apply, or weekly vector (S4).
- No CLI (S8). No live calls in tests.
- Live FP fixtures are recorded. The public key is still row-capped
  (`public_api_limited`). Projections are fetched per position; a
  combined `positions=` query only returns QB. ECR is one overall
  call (`ALL` or `OP`).
