# Handoffs

One file per session, `SN.md`, written before that session opens its PR.

One file per session means two concurrent sessions can never conflict here.

A handoff records what the next session cannot see from the code:

- the real signatures your callers will use
- what the spec got wrong or left ambiguous, and what you did about it
- anything you learned from real data that contradicts the prompt you were given
- what you did not do

See `docs/PLAN.md` section 5 for the full protocol.
