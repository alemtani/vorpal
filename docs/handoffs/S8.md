# S8 handoff

Integration. One command reads the draft, values the pool, asks the model,
and writes `board.html`. `src/vorpal/cli.py` is wiring: no arithmetic, no
joins, no policy.

Worktree is `feat/cli`.

## Run it

```sh
uv run python -m vorpal.cli \
  --draft-id DRAFT --operator NAME \
  --scoring-league-id LEAGUE \   # only when draft.league_id is null
  --override path.csv \          # only when FantasyPros is down
  --slot 4 \                     # only when the draft order is partial
  --out board.html
```

`FANTASYPROS_API_KEY` comes from the environment. `--once` writes one page
and exits; without it the poll loop runs until `draft.status == "complete"`.

There is no console script. `pyproject.toml` is a shared file (PLAN.md D5)
and adding `[project.scripts]` is a root PR, not this one.

## The flow

1. `get_draft`, `get_picks`, `get_user`, `get_league` (S1).
2. `resolve` with no `stat_columns` — this call exists only for
   `adp_variant` and `ecr_scoring` (S3).
3. `get_players_raw` and `get_players` (S1).
4. `load_forecast` **once**, before the loop (S2).
5. `resolve` again, now with the counting columns, for the real
   `LeagueConfig` and its banners.
6. Banners to stderr. Then, per poll: `compute_vols`, `build_state`,
   `build_rows`, `build_payload`, `propose`, `render` (S4, S5, S7).

**Resolve runs twice on purpose.** The ADP variant decides which forecast
to fetch; the fetched columns decide the `unknown_scoring_keys` banner;
`LeagueConfig` is frozen, so the banner cannot be added afterwards. Resolve
is pure and cheap, so the second call costs nothing. Do not try to collapse
the two — the cycle is real.

## Three module PRs this session had to open first

S8 owns `cli.py` and nothing else, so each of these is its own commit
against the package that owns it. All three were gaps, not preferences.

1. **`StatRow.bye`** (`contracts.py` + `ingest/projections.py`).
   `ProjectionRecord` carried the FantasyPros bye and `StatRow` dropped it.
   The only other bye on the board was `EcrRow.bye` — so when FantasyPros
   ECR is down, which the spec says must not block a draft, every bye on
   the board would have silently become `None` and the bye-hole gate would
   have had nothing to read. Defaulted to `None`; no caller changed.

2. **`SleeperClient.get_players_raw`** (`sleeper/client.py`). Ingest joins
   on `yahoo_id`, which lives on the wire and never reaches `Player`. The
   only alternative was reading the client's own cache file behind its
   back. `get_players` now parses the same body, so cache and parse stay
   one path.

3. **`payload/state.py` and `payload/rows.py`.** `build_payload` took a
   `DraftState` and `BoardRow`s that no module built: S3 said the snake
   arithmetic was payload state, S5 said the caller supplied it. That gap
   is the needs fill, the weekly vector, who picks between here and your
   next turn, and the VOLS/ADP/ECR/delta join. It is feature logic and it
   does not belong in a CLI.

```python
from vorpal.payload import (
    build_rows,
    build_state,
    needs_from,
    next_pick_for_slot,
    pick_no_for,
    slot_on_the_clock,
)

state = build_state(
    pick_no=len(picks) + 1,
    slots=config.slots,
    teams=config.teams,
    rounds=config.rounds,
    seat=resolved.seat,  # None ⇒ next_user_pick / picks_until_next /
    picks=picks,  # between are all omitted, never guessed
    pool=pool,  # dict[str, ScoredPlayer]
)

rows = build_rows(
    vols_result,
    pool=pool,
    available=frozenset(pool) - drafted,
    adp={...},  # StatRow.adp, already the chosen variant
    ecr={...},  # player_id -> EcrRow
    roster=[...],  # the operator's ScoredPlayers
    slots=config.slots,
    teams=...,
    rounds=...,
    pick_no=...,
    needs=state.needs,
)
```

`build_rows` **caps first, then computes the delta.** `delta_starter_points`
is two 18-week fills per candidate. Over a 700-player pool that is 25,000
fills on a 3-second poll. Over a capped board it is 120. Capping a capped
board is idempotent — arm 1 is the top 50 either way, arm 2 is the top
`depth` per position either way — so nothing is lost by letting
`build_payload` cap again.

## Things the next session cannot see from the code

- **The forecast is fetched once and the test proves it.**
  `test_the_forecast_is_fetched_once_however_long_the_draft_runs` counts
  six projection calls, one per position, for a whole run. If someone moves
  `load_forecast` inside `recompute`, that test is what fails.
- **The four refusal classes keep four different words** — `unsupported
  league`, `data refusal`, `platform error`, `user refusal` — one e2e test
  each. `_label` falls back to `error` for a bare `VorpalError`.
- **`propose`, never `recommend`.** A degraded pick writes a board with the
  violations as `violation_*` banners and exits 0. Only a transport failure
  is a `PlatformError`.
- **The client's backoff is the only backoff.** S1 waits before the next
  HTTP call after a failure; S7's loop waits after a `PlatformError`.
  Wall-clock `sleep` is injected into `run_loop` and nowhere else, so the
  two do not compound in tests.
- **`FP_MIN_INTERVAL_S` is 1.1 seconds** — live FantasyPros allows one call
  a second, and there are eight calls. The e2e fixture monkeypatches it to
  0; a suite that does not is a minute slower per case.
- **Keepers never reach the pool.** `resolved.keeper_ids` filters `_pool`,
  so a keeper cannot be recommended and cannot be a replacement.

## E2E fixtures

`tests/e2e/league.py` builds a synthetic league — 200 players, a host
`/players` map and a FantasyPros projection file generated from one list,
one yahoo id apart. The recorded `players.json` is a redacted subset, so
joining it to a real projection file trips S2's 98% mapping gate; these
fixtures make the join exact so the test measures wiring, not matching.
The draft, league, user, and scoring settings are the recorded bytes.

`conftest.py` names every respx route (`api["draft"]`,
`api["projections_QB"]`, `api["adp"]`, `api["ecr"]`, …) so a case can fail
one host without re-registering the rest. respx matches in registration
order; an unnamed override added later never wins.

`HintTransport` reads `hint_argmax_vols` off the payload and answers with
it. `StubTransport({"nonsense": True})` drives the degraded path.

## Spec vs this session

1. **SPEC.md §2 lists the scoring-source league as required iff
   `draft.league_id` is null.** The CLI passes `--scoring-league-id`
   straight to `resolve` and lets it decide; there is no second check here.
   A mock with no league is `UserRefusal`, an attached draft with a
   mismatched league is `DataRefusal`, and both messages come from S3.
2. **The S8 prompt ordered resolve before the forecast fetch.** S3 already
   flagged that the unknown-key banner needs the columns. Two resolve calls
   is the resolution; see above.
3. **`market_only` rows stay in the pool and off the board.** S4 excludes
   them from VOLS, so `build_rows` never sees them. That is SPEC.md §4, not
   an omission.

## What S8 did not do

- No console script, no `pyproject.toml` edit, no README.
- No eval run or baseline table (S10). No golden or regret fixtures (S9).
- No live network anywhere. `-m live` is still S5's model test only.
- No `should_stop` plumbing: `KeyboardInterrupt` stops the loop, and the
  last written `board.html` stays on disk.
